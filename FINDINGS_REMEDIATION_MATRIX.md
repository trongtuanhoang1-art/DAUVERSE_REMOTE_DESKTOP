## 2. Detailed Root Cause & RC3 Implementation Notes for Residual & New Findings

### A. F01 — Lossless IEEE-754 Canonicalization & Strict Wire Parsing (`P1`)
- **Re-QA 006 Residual Root Cause:** `DAUVERSE_AI_EVENT_V2` formatted `progress` (`Option<f32>`) and `confidence` (`f32`) to 4 decimal places (`"{:.4}"`), allowing distinct `f32` bit patterns (e.g. `100.0f32` `0x42c80000` vs `100.00000762939453f32` `0x42c80001`) to produce identical HMAC tags while normalizing differently (`Some(100.0)` vs `None` because `> 100.0`). Additionally, `SignedAiEventEnvelope` had `#[serde(default)]` on `schema_version`, lacked `#[serde(deny_unknown_fields)]`, and the loopback HTTP gateway used `from_utf8_lossy` and accepted short bodies when `Content-Length` exceeded bytes sent.
- **RC3 Fix:**
  - Upgraded protocol to `AI_EVENT_SCHEMA_V3 = 3` (`"DAUVERSE_AI_EVENT_V3"`), rejecting `schema_version < 3`.
  - Replaced lossy decimal formatting with `canonical_f32_tag(value, min, max)` emitting exact big-endian IEEE-754 binary32 hex tags (`"f32:{bits:08x}"`), rejecting `NaN`, `±Infinity`, negative zero (`0x80000000`), and out-of-range values (`progress` outside `[0.0, 100.0]`, `confidence` outside `[0.0, 1.0]`) **before** signing and **before** verification across `src/dauverse/ai_bridge.rs`, `scripts/hooks/claude_code_hook.py`, `scripts/hooks/codex_notify_hook.py`, and `scripts/hooks/dauverse_job_wrapper.ps1`.
  - Added `#[serde(deny_unknown_fields)]` to `SignedAiEventEnvelope`, `AiEvent`, `EventProvenance`, and `ReplayRecord`, removed `#[serde(default)]` on `schema_version`, and enforced strict `std::str::from_utf8` + exact `Content-Length` body reads (`HTTP 400`) in `spawn_loopback_http_gateway_with_sink` (with strict `UTF8Encoding($false, $true)` in PowerShell).
- **Pre-Fix FAIL -> Post-Fix PASS Proof:** `scratch_rc2_rust_repro.log` (`rc3_probe_f01_v2_float_bucket_collision_allows_semantic_drift` FAILED on `0e1e3e871`) -> PASS in `dauverse::ai_bridge::tests`, `TESTS/test_e2e_hooks_and_secrets.py`, and `TESTS/test_rc3_powershell_validators.py`.

### B. F09 & F07 — Fail-Closed Replay Journal & Security State Persistence (`P2` / `P1`)
- **Re-QA 006 Residual Root Cause:** `AiEventBridge::load_persisted_journal` treated any read/JSON failure on an existing `bridge_replay_journal.json` identically to a missing file, resetting the replay cache to empty after restart. Similarly, `DeviceShieldSecurityCenter::verify_step_up_passcode_at` ignored `self.persist_security_state()` errors (`let _ = ...`), and `symlink_metadata(...).is_ok()` conflated `PermissionDenied` with `NotFound`.
- **RC3 Fix:**
  - Replaced `load_persisted_journal` with `load_replay_journal_strict` in `src/dauverse/ai_bridge.rs`: only `ErrorKind::NotFound` starts fresh; any stat error, `open_no_follow_regular_file` error, UTF-8 error, malformed JSON, unknown field, or invalid record latches `journal_corrupted_fail_closed = true` and rejects **all** event ingestions with `EVENT_REJECT_REPLAY_JOURNAL_CORRUPTED_FAIL_CLOSED` (`HTTP 503`).
  - Propagated `persist_security_state()` failures in `src/dauverse/security.rs` (`verify_step_up_passcode_at` both failure/lockout and success branches, `pair_trusted_device` with in-memory rollback, and `revoke_device`), latching `state_corrupted_fail_closed = true` and returning `Err("SECURITY_STATE_PERSIST_FAILED_FAIL_CLOSED: ...")`.
  - Hardened `src/dauverse/notifications.rs` (`open_no_follow_regular_file` + `journal_corrupted` fail-closed write guard) and `src/dauverse/mod.rs` (`dashboard_snapshot.storage_healthy` aggregating replay, notification, settings, and security persistence health).
- **Pre-Fix FAIL -> Post-Fix PASS Proof:** `scratch_rc2_rust_repro.log` (`rc3_probe_f09_corrupt_replay_journal_silently_resets_cache` & `rc3_probe_f07_f05_lockout_persist_failure_ignored` FAILED on `0e1e3e871`) -> PASS in `dauverse::ai_bridge::tests`, `dauverse::security::tests`, and `phase4_corrupt_replay` (`HTTP 503`).

### C. F11 & F02 — Bidirectional Backup/Release Manifest Closure & Validator Hardening (`P2` / `P1`)
- **Re-QA 006 Residual Root Cause:** `Assert-BackupManifestIntegrity` (`rollback_windows_release.ps1`) and `Assert-ManifestFileValid` (`verify_and_package_windows_rc.ps1`) checked `manifest -> disk` without checking `disk -> manifest`, allowing unlisted extra files in `.rollback_backup` to be copied into `$InstallDir` by `Copy-Item -Recurse`; `Assert-OriginalBuildLogValid` accepted any `>=1024`-byte text containing `BUILD_WINDOWS_RC_DONE`; and Stage `[6/7]` tested rollback using identical PE binaries with only JSON sentinel differences.
- **RC3 Fix:**
  - Enforced full bidirectional `manifest <-> disk` closure in both `rollback_windows_release.ps1` and `verify_and_package_windows_rc.ps1` (rejecting unlisted files, directory junctions/reparse points, ADS `:`, `..`, trailing dots, and duplicates).
  - Replaced whole-folder `Copy-Item -Recurse` in `rollback_windows_release.ps1` with `Get-VerifiedManifestRelativeFiles` so **only** manifest-verified files are restored, followed by bidirectional post-restore verification.
  - Updated `Assert-OriginalBuildLogValid` to enforce 9 ordered native build stage markers (`RepoRoot`, `CargoTarget`, `flutter pub get`, `Build dylib_virtual_display`, `Build librustdesk.dll`, `flutter build windows --release`, `Generate single-file portable executable`, `Compile NSIS Setup Installer`, `=== NATIVE COMPILATION & PACKAGING SUCCEEDED ===`), expanded Stage `[0/7]` to 12 negative selftests, and updated Stage `[6/7]` to test distinct pre-upgrade vs post-upgrade `DAUVERSE_REMOTE.exe` PE hashes plus unlisted-backup-extra rejection.
- **Pre-Fix FAIL -> Post-Fix PASS Proof:** `scratch_rc2_ps_repro.json` (4 PowerShell validator bypasses reproduced on `0e1e3e871`) -> PASS in `TESTS/test_rc3_powershell_validators.py`.

### D. F14 — Windows Handle Final-Path Confinement & Unprivileged Junction Tests (`P2`)
- **Re-QA 006 Residual Root Cause:** `src/dauverse/crypto_util.rs` checked `starts_with` on `GetFinalPathNameByHandleW` strings without enforcing a path-component boundary (`E:\allowed` matched `E:\allowed2\x`), skipped verification when `len == 0` or `len >= 1024`, `validate_no_symlink_components` in `libs/base/src/fs.rs` did not check `FILE_ATTRIBUTE_REPARSE_POINT` (`0x0400`) on NTFS junctions, and 2 directory symlink tests in `libs/base` were `#[cfg_attr(windows, ignore)]`.
- **RC3 Fix:**
  - Added `verify_windows_final_path_confined` and dynamic-retry fail-closed `query_windows_final_handle_path` (`len == 0` or overflow -> `Err`) in `src/dauverse/crypto_util.rs` (applied to both `write_atomic_bytes` and `sha256_file_confined_no_follow`) and `verify_windows_handle_confined` in `libs/base/src/fs.rs`, normalizing `\\?\`, `\??\`, and `\\?\UNC\`, rejecting `\\.\` device paths and NTFS ADS `:`, and comparing parsed volume authorities + path segments component-by-component.
  - Added `FILE_ATTRIBUTE_REPARSE_POINT` (`0x0400`) rejection to `validate_no_symlink_components` in `libs/base/src/fs.rs` and removed `#[cfg_attr(windows, ignore)]` from `path_traversal_e2e_write_rejects_symlink_escape` and `download_refuses_symlink_destination_directory` via unprivileged `cmd /C mklink /J` fallback, plus added `f14_f16_download_refuses_hardlinked_staging_and_sha256_mismatch`.

### E. F16 — End-to-End Per-File Sender–Receiver SHA-256 & Byte-Length Binding (`P2` / Priority §3.E)
- **Re-QA 006 Residual Root Cause:** `TransferQueueManager::verify_and_finalize_engine_receive` allowed `expected_sha256 == None` to finalize as `TransferStatus::Completed` (`LOCAL_SHA256_COMPUTED_SIZE_VERIFIED`) after checking only aggregate `actual_total_bytes == expected_total`, permitting same-size content corruption (`AAAA` -> `BBBB`) and compensating multi-file byte-length swaps (`[4, 6]` vs `[2, 8]`).
- **RC3 Fix:**
  - Added `string sha256 = 6;` to `FileEntry` in `libs/base/protos/message.proto`.
  - Computed exact `(sha256, size)` for every file in `TransferJob::new_read` (`libs/base/src/fs.rs`), tracked streaming SHA-256 + byte count in `TransferJob::read` (aborting before `FileTransferDone` if a sender file mutates mid-transfer), and verified `.download` staging SHA-256 + byte length before rename in both `TransferJob::modify_time` and `TransferJob::finish_download` (`libs/base/src/fs/download.rs`).
  - Extended `ipc::FS::NewWrite` (`src/ipc.rs`, `src/server/connection.rs`, `src/ui_cm_interface.rs`) and client download handlers (`src/client/io_loop.rs`) to register `ExpectedFileIntegritySpec { relative_path, expected_bytes, expected_sha256 }` for every file (handling both single-file empty `entry.name` and multi-file folder transfers).
  - Updated `finalize_and_verify` and `verify_and_finalize_engine_receive` (`src/dauverse/transfer_guard.rs`) to **never** mark `TransferStatus::Completed` without a valid 64-char hex sender SHA-256 per file, checking unconditional `.download`/`.digest` leftovers, exact per-file `expected_bytes`, constant-time per-file SHA-256 equality, and aggregate total parity.
- **Pre-Fix FAIL -> Post-Fix PASS Proof:** `scratch_rc2_rust_repro.log` (`rc3_probe_f16_compensating_multi_file_sizes_and_missing_sender_hash_marked_completed` FAILED on `0e1e3e871`) -> PASS in `base::fs::tests`, `dauverse::transfer_guard::tests`, and `TESTS/test_e2e_hooks_and_secrets.py`.

### F. F08 — OS-Verified Service & Auto-Start Revocation (`P2`)
- **Re-QA 006 Residual Root Cause:** `ServiceController::revoke_all_access_immediately` deleted `HKCU Run` best-effort (`let _ = ...`) and flipped `g.service_state` from `Running` to `Stopped` in memory without stopping the Windows SCM service or verifying OS state, causing `"revoke_all_access"` FFI to report `ok: true` unconditionally.
- **RC3 Fix:**
  - Changed `revoke_all_access_immediately(&self) -> Result<ServiceStartupState, String>` (`src/dauverse/service_ctrl.rs`): sets `approve-mode = "click"`, disables keyboard/clipboard/file-transfer, sets `stop-service = "Y"`, rotates temporary password, verifies `Config::get_option("approve-mode") == "click"`, deletes owned `HKCU Run\DauverseRemoteDesktop` with error propagation, stops **owned** (`owned == Some(true)`) SCM `RustDesk` via `windows_service` (`ServiceAccess::STOP | QUERY_STATUS`) while strictly leaving external (`owned == Some(false)`) `RustDesk` services untouched, re-observes actual OS state via `self.status()`, and returns `Err` (`ok: false` + `"FAILED"` audit in `src/dauverse/ffi.rs`) if OS verification fails. Also revokes all active `DeviceShieldSecurityCenter` sessions and step-up tokens.

### G. N01 — Exact Microsecond HMAC Benchmark Scaling (`P2`)
- **Re-QA 006 Root Cause:** `src/dauverse/performance.rs:466` computed `hmac_event_sign_us: (sign_us * 100.0).round() / 1000.0`, dividing microsecond latency by an extra factor of `10` (`0.228 µs` reported instead of `~2.28 µs`).
- **RC3 Fix:** Added `PerformanceEngine::round_3dp` (`(value * 1000.0).round() / 1000.0`) and `compute_per_iteration_us`, recorded `hmac_iterations: 200` and `hmac_total_elapsed_us` alongside `hmac_event_sign_us`, regenerated `ARTIFACTS/evidence/benchmark_results.json` from the fixed release `.so`, and added `n01_benchmark_hmac_sign_us_preserves_exact_microsecond_scale_and_rounding` + E2E consistency assertions.
